# 商品封面生成与剪映草稿封面研究

## 已确认结论

- 用户确认“封面”是剪映草稿列表封面，不是视频时间线中的图片素材。
- 商品图片接口来自导出的星斗 HAR：商品详情响应的 `data.images` 是图片列表。实现只下载 `p3-aio.ecombdimg.com` 和 `p9-aio.ecombdimg.com` 的 HTTPS 图片，保存为当前项目工作目录中的参考图。
- 生图服务按 OpenAI Images API 兼容协议接入，使用独立 Base URL、模型 ID 和 API Key，默认请求 `/images/edits`，通过 multipart 的 `image` 字段上传参考图，接受 `b64_json` 或同域 HTTPS 图片 URL。
- 封面任务绑定 `asset_id`、`plan_id` 和 `revision`。有未保存片段调整时禁止提交，生成草稿时校验封面与当前方案修订一致。
- 星斗商品图片按项目和商品 ID 缓存已下载文件；再次打开流程复用本地图片，只有用户点击“重新获取”才重新请求商品详情并更新缓存。
- 封面画面必须同时展示人物上身效果图和同款未上身商品单品图：人物上身效果作为主要主体，较小的单品图放在旁边作辅助对照；两者款式、颜色和细节应一致，不以品类文字替代单品图。商品参考图可为上身图或单品图，Prompt 要求模型补足另一种展示。参考图加载期间及单张图片加载失败时用骨架占位，失败图片不可选。
- 弹窗内生成要求与封面预览左右布局。生成前的预览用普通空状态；生图中及生成结果图片加载时，仅在封面图框中显示骨架，失败后显示错误占位。商品参考图的骨架也仅出现在图片框内，不使用覆盖整弹窗的加载态。
- 带封面草稿采用生成新版目录的方式，保留既有草稿。生成器保留 3:4 JPG 的像素尺寸后复制到 `Resources/cover/`，用独立图片子草稿填充 `cover.cover_draft` 并保留 `cover_draft_id` / `materials.drafts` 关联，同时输出根目录 `draft_cover.jpg` 列表缩略图及 `draft_meta_info.json.draft_cover`；当前版本不写入根级 `static_cover_image_path`。剪映 11.8.0.14778 的 3:4 自动补图效果仍待实机验收。

## 放弃的方案及原因

- 放弃直接修改用户已有剪映草稿：需要识别并安全更新已有目录中的工程元数据，容易覆盖用户在剪映中的后续编辑，也无法稳定处理已有草稿正在被剪映读取的情况。采用生成新版草稿目录并保留旧草稿，边界更清楚且符合用户确认。
- 放弃把星斗带签名图片 URL 直接交给生图服务或写入项目数据：链接可能过期，并会把平台临时凭据带入任务 / 草稿；改为先下载到项目工作目录，再上传本地参考图。
- 暂不接入独立服务的专有请求格式：用户尚未提供真实协议样例，当前只实现 OpenAI Images API 兼容协议，真实服务字段差异留待接入时验证。
- 放弃生图前单独调用文本模型生成封面短名称：这会增加一次模型请求和弹窗等待，也把标题生成与封面构图拆成两个模型步骤；改为在生图 Prompt 中提供商品原名，由生图模型提炼并排版简短标题。
- 放弃只在商品图片接口返回前显示骨架、返回后立即露出尚未加载的缩略图：浏览器异步载入图片期间仍会出现空白；改为每张缩略图加载完成前持续显示骨架，加载失败时保留占位并禁用选择。
- 放弃在封面生成过程中以一个大骨架占满预览容器或让商品查询骨架铺满整个图片网格：骨架只应代表尚未呈现的图片，不应替代表单或其他弹窗内容；改为仅在商品图和封面图各自的固定比例图片框显示占位。
- 更正此前“封面不出现人物、只展示未上身单品图”的要求：用户确认封面要同时展示人物上身效果和同款单品图，人物图为主、单品图较小并列；旧的无人物描述已从当前提示词和规格中移除。
- 放弃按源视频画布选择横屏、竖屏或方形封面尺寸：封面用途固定为抖音视频封面，不跟随视频画布比例。生图请求使用标准竖版尺寸以兼容 OpenAI Images API 服务，再用 FFmpeg 居中裁切为精确 3:4 PNG。
