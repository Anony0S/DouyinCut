## 4. ASR 协议与时间映射

- 语音模型可填写 `qwen-audio-3.1-asr-flash` 等支持当前音频协议与句级时间戳的模型 ID，不自动填入。模型可用性以实际账号为准，不作最新型号声明。
- 文本 Base URL 示例：`https://dashscope.aliyuncs.com/compatible-mode/v1`，请求追加 `/chat/completions`；语音 Base URL 示例：`https://dashscope.aliyuncs.com`，独立追加 `/api/v1/services/aigc/multimodal-generation/generation`。两项地址均由用户手动填写，语音网关前缀按配置保留，不从文本地址推导。
- 两类自定义 Base URL 均必须 HTTPS，禁止嵌入用户名、密码、查询参数、片段或完整操作路径；各自的密钥发送到各自填写的主机，不跟随重定向。文本读取 `llm_api_key`，语音读取 `asr_api_key`，不互相回退或自动改写模型 ID。创建分析前检查两个密钥均已配置。
- 本地提取最多 **120 秒**单声道、16kHz、PCM WAV，尾段不足 120 秒正常处理；小于 1 秒的 ffprobe 舍入尾差直接跳过，不上传空 WAV。处于用户要求的 2–3 分钟范围。30 分钟最多 15 次语音请求，串行处理并更新进度。
- 音频上传私有 OSS，经临时签名 URL 传入 `input.messages[].content[].input_audio.data`；请求 `parameters.format="wav"`、`sample_rate="16000"`、`X-DashScope-SSE: disable`，ASR 单次等待使用任务快照的 asr_timeout_seconds，默认 300 秒，可配置 30–900 秒。
- 解析顶层 / output 的 `sentence` 或 `sentences` 对象 / 数组，重复镜像只解析一次。支持 text / 聊天式内容解析，但精确粗剪必须有效句级时间戳。
- `begin_time` / `end_time` 为段内整数毫秒，转换为微秒并加源音频偏移。拒绝未完成句子、非法时间和重叠。words 不重复追加已有句子文本，若 sentence 包含长段口播且带 words，按真实词级时间与标点 / 停顿拆分为短句，校验 words 完整覆盖原话。标点逗号等在当前分组达到约 3.5 秒后拆分，并设置 8 秒硬上限，使剪辑决策可使用更细粒度行。逐词字幕样式仍延期。
- 句内最后一个有文本的词（须为 `words` 最后一项）若起点早于音频段尾，且结束时间最多超出段尾 50 毫秒，解析时将结束时间截到段尾可用的最后一个整毫秒。其他词级越界报错并显示词序号、返回区间和越界量。句级时间戳仍按音频段范围严格校验。修正后的转写继续检查文本完整性与重叠，成功缓存保留脱敏原始时间戳。
- 导入探测保存音频 / 视频流起始时间；内部转写区间相对音频起点。ASR 音频提取和导出使用音频流起点加源区间，按绝对媒体时间戳精确定位；导出时音视频共用一次输入 seek，保留两条流原有的 PTS 同步关系。源片段播放器将音频相对媒体起点的偏移换算为浏览器时间，不按视频流起点额外推进口播。商品视频片段以 TS 导入项目时，在 import 任务中转为 H.264/AAC MP4，项目引用转换后的 MP4，原始录制文件保留；商品片段切分按 [§2.4](live-monitoring.md#24-抖音直播监控) 在临时目录中无损重封装 TS，再对选区一次编码生成 MP4，临时来源随任务结束清理。上述 import 转换先检测编码：H.264 视频与 AAC 音频直接重封装，只有不兼容的流才编码为 H.264/AAC；若混流失败则回退完整转码。普通本地 TS 上传不自动转换。
- 仅整段文本时明确报错，不将两分钟粗略时间当作精细切点，不静默退回 10 秒重提。成功文本缓存保留，不能因缺少时间戳自动重复收费。
- 不得将整段两分钟口播的一组 begin_time / end_time 当作一句。未包含可拆分的词级时间时明确报错，不按文字长度猜时间。
- 成功缓存保存完整脱敏 ASR 返回以支持重新解析词级时间；用户可主动勾选“重新识别语音”，界面明确说明会再次调用 ASR。刷新结果按本次任务复用，不能绕过不确定提交保护，也不持续开启刷新选项。
- 缓存按素材摘要、实际源区间、模型与接口隔离；更换要求复用成功 ASR。明确拒绝允许修正后重试；普通超时 / 408 / 5xx 保留不确定提交标记并停止自动重提，需核查云端请求。有明确记录的显式退出中断按 [退出中断重试 ADR](../../../docs/adr/0001-exit-interrupted-cloud-retry.md) 在下次启动直接重排；该例外不解除一般网络异常保护，也不清空成功缓存。
- **待验证：120 秒真实输入限制、长音频多句返回完整性、模型效果和实际边界精度。**如真实账号不支持，明确展示错误，再修订协议或分段规格。
- OSS 需要对象读写权限；建议为 `douyincut/audio/` 配置生命周期。相同素材分段的确定性对象键每次上传都会覆盖，避免复用空 / 损坏音频；应用暂不自动删除远端对象。

## 5. 全量对话决策与时间区间剪辑

决策模型由用户手动配置，例如 `qwen3.8-flash`。整个视频 ASR 完成后，将商品名称、剪辑要求、目标时长、允许偏差及句级转写一次性交给文本模型，剪辑要求留空时使用默认要求。两分钟是 ASR 上传单位。转写每句使用紧凑数组 `[index,start_ms,end_ms,text]`，按实际提交的转写数组从 0 编号，时间为源视频绝对整数毫秒。所有视频内容作为不可信素材数据处理。完整转写单独保存，决策失败后仍可查看。

默认发送全部转写。分析前可开启“过滤短语气词”并设置两个门槛，初始值为少于 5 字且短于 1 秒。忽略空白和标点后，只有完全由预设语气字构成且同时低于两个门槛的句子才从模型输入省略。若所有句子都符合过滤条件，发送完整转写。原始转写用于 ASR 缓存、查看、句界校验和字幕生成。选片跨过被省略的句子时仍保留对应原声。

决策 Prompt 要求返回形如 `{"clips":[{"start_index":2,"end_index":4}]}` 的 JSON 对象。每段包含首尾两句，选一句时两个索引相同。程序按本次提交的转写查出首句的开始时间和末句的结束时间，将它们作为裁剪、缓存及结果记录所用的毫秒区间。数组顺序即拼接顺序，允许跨 ASR 上传边界。单段最多 10 秒，优先选择 3–8 秒且表达完整的独立卖点。删除中间内容时拆成多个区间。只保留目标商品相关内容，排除其他商品 / 款式、商品切换后的内容、价格、优惠、催单、直播互动、重复话术及无关内容。程序校验索引顺序和范围，以及区间的时长、素材、重叠和重复。

模型从提供的对话挑选有价值的短片段，提示携带 duration_tolerance_ms、max_total_duration_ms 与 max_clip_duration_ms，并要求逐项求和核对；新任务快照保存 duration_tolerance_us 和 short_filler_filter。总时长按目标 + 当前偏差校验，缓存决策重新进入 worker 时也使用该任务的偏差；拼接方案的时长提示使用同一数值。默认偏差为 15 秒，因此默认 60 秒时合计最多 75 秒，90 秒时合计最多 105 秒。素材不足可更短。

模型返回可解析的选片时先校验原始句界、素材引用、重复和重叠。超过 10 秒的连续区间，若可在 ASR 前句结束等于后句开始的共享整数毫秒边界完整拆分，则本地按每次不超过 10 秒的最远句界拆分，保留源区间全部内容、顺序和总时长，不额外请求模型；例如 10.8 秒的三句连续口播可拆为 7.96 秒和 2.84 秒。没有可用共享句界、单句本身超过上限或拆分结果超过 100 段时不强拆，也不删除句间空隙或编造切点。拆分后仍须遵守总时长上限，不能用拆分代替精简。

选片索引越界或首尾倒序，或经过拆分后仍超过单段或总时长上限时，沿用首次提交的转写、商品与用户要求，并附带前次模型返回的索引。索引纠正指出无效片段、索引和有效范围，要求模型依据原转写重新选择并尽量保留其他片段及顺序。时长纠正提供实际总时长、允许上限、至少需减少的时长和最长单段时长，要求删减次要或重复卖点。模型须返回全部 clips。

索引与时长共用最多两次纠正请求（含首次合计最多三次文本模型请求），沿用已有 ASR / OSS 数据和时长限制。切点必须来自 ASR 句界。只有通过全部校验的决策才能缓存并发布方案。用尽纠正次数时显示最后的校验问题和完整模型回复。无效 JSON、无可用片段、重复、重叠和网络失败均直接报告，网络失败保留原错误详情。纠正请求与首次请求使用相同连接、超时和可中断子进程机制。追加请求前检查暂停 / 取消 / 退出状态，每次请求独立记录云端操作。价格等按用户要求排除，不能编造口播或时间，不能将整段视频当作成功粗剪。短片段有助于去除冗余口播和商品切换内容，但系统不承诺平台同质化审核结果；当前无画面识别。

模型须从全部入选内容中选择最适合开头、吸引注意且可独立理解的完整口播作为 clips 第一项。优先明确商品利益点、穿着效果或痛点回应，避免寒暄和依赖前文的半句话，不编造承诺。随后按卖点与说明安排成片叙事顺序，保持指代、因果和衔接自然，用户明确的顺序要求优先。全量 ASR 按源时间排列供阅读上下文，模型按成片需要决定 clips 顺序。纠正后也须确认开头与叙事顺序。程序、入选片段列表和导出均保留 clips 数组顺序，本地拆分在原片段位置依次展开。

程序按每个区间分别裁剪原视频，按返回顺序拼接，并对最终拼接结果统一编码以连续化各片段的视频时间戳 / GOP 边界；输出时长应接近所有区间时长之和。不能回退播放或导出原视频作为粗剪结果。

决策请求非流式，输出最多 16000 tokens（推理模型的思考也计入该额度）；输出被截断（finish_reason=length）或正文为空时明确报告原因，结构校验失败时指出具体字段；等待默认 300 秒，可配置 30–900 秒，只用于新任务快照。应用可读取纯 JSON，也可从带分析文字的回复中提取唯一、完整的 JSON 代码块。区间自带的额外说明字段会丢弃。缺少唯一 JSON 时报告格式问题，完整云端响应保留在错误详情。决策失败保留 ASR 缓存及全量转写；不得发布半成品商品 / 候选 / 方案。
