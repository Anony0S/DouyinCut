# 产品目标与使用前提

[返回项目规格与文档入口](index.md)。维护规则和迁移来源见索引；原章节编号保留用于追溯。

## 1. 目标与使用前提

**输入视频主要讲同一款商品**，用户填写商品资料，应用根据口播识别与剪辑要求，生成约一分钟的粗剪并自动拼接预览，确认后生成剪映草稿继续精剪。

当前主流程：视频项目列表 → 新建并选择本地视频，或从直播监控导入商品视频片段 / 打开已有项目 → 填写商品名称、剪辑要求、目标时长与允许偏差 → 分段 ASR → 汇总全量对话与源时间戳 → 文本模型选择时间区间 → 自动拼接预览 → 调整 / 重新粗剪 → 生成剪映草稿。

- 商品名称必填，示例：独束分身型微定制【奶黄千层】假两件针织开衫。
- 编辑页不再提供“补充信息（可选）”，当前项目草稿、分析请求及模型提示中移除此字段。商品事实以源视频口播为准，不能编造视频中没有的内容。
- 默认剪辑要求：“保留上身效果、版型、面料和穿着感受的介绍，去掉价格、优惠、催单、无关互动及重复口播，保持表达完整，生成约 60 秒的视频。”可修改；空白使用内置要求。“保存为默认”独立于分析执行，将当前要求保存到本机应用设置并同时保存当前项目草稿，后续新项目和未填写要求的项目自动使用；已有项目的已保存要求仍优先。分析失败不回滚默认要求，刷新或重启后继续保留。
- 默认目标 60 秒，界面可选 90 秒。素材不足生成较短版本；允许偏差通过滑块以 1 秒为步长在 0–30 秒调整，默认 15 秒，实时显示 ±N 秒与建议时长范围。滑块采用 daisyUI 的 Range with custom color and no fill 形式：主题主色滑块、主题分隔色轨道，关闭进度填充，浅色 / 深色随主题适配。模型优先落在目标 ± 偏差内，素材不足可更短；实际总时长不得超过目标 + 偏差。模型超过总时长或单段上限时自动反馈实测时长并要求精简，最多纠正两次，仍不合格才报错。
- “上身效果 / 面料”指相关口播，本版未检查画面是否正在展示相应内容。
- 粗剪分析不调用视觉模型、不抽帧、不识别或合并多款商品，不要求手动建立商品、确认归属或标注候选；直播讲解轨道的本地悬停缩略图仅用于人工预览。
- 抖音直播监控（首版，详见 [§2.4](live-monitoring.md#24-抖音直播监控)）：对用户呈现为一场连续录制，内部保留可恢复的 MPEG-TS 媒体分块；记录商品讲解切换，用户可手动将已封存讲解区间切分为商品片段。商品视频片段可导入为视频项目，导入后由用户填写商品资料并主动启动 ASR / 粗剪，不自动调用模型。内部媒体分块不单独作为项目素材呈现。抖音解析参考 StreamCap 的公开实现并依赖 `streamget`；平台接口易变化，真实账号 / 开播及 FFmpeg 音画需单独验证。
- 剪映草稿（详见 [§2.3](workspace.md#23-任务与交付)）：可将已保存的粗剪方案及字幕生成剪映可编辑草稿；实际剪映 11.6.0 打开验证仍须单独完成。
- 暂不纳入首版验收：主播主页链接、跨批次商品池、直播断线自动续录、多直播间并行可靠性、视觉理解与应用内字幕编辑。
- 长期设计保存在 [docs/FUTURE_DESIGN.md](../../../docs/FUTURE_DESIGN.md)，不构成本版验收要求。
