# 软件更新与 GitHub Releases 发布

Windows x64 正式安装版在「本地设置 → 版本更新」中提供手动检查、下载、进度与取消，以及确认后退出安装。应用不会在启动时自动检查或下载。更新源固定为公开仓库 [Anony0S/DouyinCut](https://github.com/Anony0S/DouyinCut) 的最新正式 Release；不需要用户配置 GitHub Token。

## 使用流程

1. 点击「检查更新」，查看新版本和更新说明。
2. 点击「下载」，等待完整下载及 SHA-256 校验。切换页面不影响下载，退出应用会中断下载；下次需重新检查和下载，不续传。
3. 点击「退出并安装」。有未保存内容时，先保存或明确放弃；录制中或准备录制时须先停录。
4. 确认退出。活动任务会按现有安全退出流程处理；未完成的云端请求可能在下次启动后重发并产生额外费用。
5. 安装器等待旧程序退出后打开安装向导，覆盖当前安装目录。完成后可从向导重新启动应用。

取消确认不会删除已下载的安装包，当前应用会话中仍可再次安装。更新缓存与用户工作目录分开；更新不删除项目、原始视频、录制文件、云端连接设置或凭据。开发桌面外壳可以检查和下载，但不能执行安装；浏览器开发页面不支持原生命令。

## 发布一个版本

1. 修改 [SPEC.md](../SPEC.md) 顶部规格版本并提交对应代码。界面、原生程序和安装器均读取该版本。
2. 在 Windows 构建：

   ```powershell
   .\scripts\build-windows-installer.ps1
   ```

3. 在 [Releases 页面](https://github.com/Anony0S/DouyinCut/releases/new) 创建 Release，标签为 `v<规格版本>`，例如 `v0.2.137`。使用正式发布，不勾选预发布，并确保该版本为 Latest。标题和正文填写用户可读的更新说明。
4. 同时上传构建输出的两个附件，文件名必须与标签版本一致：

   ```text
   DouyinCut-0.2.137-setup.exe
   DouyinCut-0.2.137-setup.exe.sha256
   ```

   输出目录为 `desktop/src-tauri/target/release/installer/`。构建自动生成校验附件及包含标签 / 附件路径的构建清单；源码 ZIP/TAR 不作为更新安装包。

校验文件为 UTF-8 文本，内容是一行 SHA-256 和准确的安装包文件名：

```text
<64位十六进制SHA-256>  DouyinCut-0.2.137-setup.exe
```

如果构建后对安装包做 Authenticode 签名或其他修改，必须在最终文件上重新生成校验附件，再上传：

```powershell
uv run python scripts/prepare-github-release.py --installer desktop/src-tauri/target/release/installer/DouyinCut-0.2.137-setup.exe
```

标签、安装包名称、校验文件名称和内部文件名任何一处不一致都会拒绝下载。无正式 Release 时显示尚未发布；低版本或同版本不会触发降级 / 重装。网络错误、GitHub 请求限流、缺失附件、下载中断或校验失败会显示原因，允许重试。

## 实现与信任边界

当前发行物是 Inno Setup 安装器，因此使用原生 GitHub Release 检查和安装器交接，不使用 Tauri updater 的 `latest.json`、NSIS/MSI 包或其签名格式。检查通过 GitHub API，附件仅从固定官方仓库的 HTTPS 地址及允许的 GitHub 附件域名下载。下载限制为 2 GiB，单次读取停滞 30 秒或总下载超过 15 分钟会失败。

SHA-256 用于检查传输完整性；安装前会再次计算。校验文件与安装包同源，当前没有独立发布者签名，安全性依赖 GitHub 仓库账户与 HTTPS。代码不包含发布凭据或签名私钥。

更新不会提供历史业务格式迁移，沿用当前开发规格的数据约定。第一个带此功能的版本仍需手动安装，之后才能通过应用内更新。

## 验收范围

本次新增版本比较、附件约束、下载完整性、取消及退出保护测试，并验证前端生产构建、Rust 编译与安装脚本编译。这些检查不等同于真实覆盖安装验收。

正式上线前，需要用两个真实版本在隔离 Windows 环境验证：旧版本发现新正式版，完整下载 / 取消重试，草稿保护、录制阻止、任务暂停和安全退出，安装器等待旧进程，覆盖安装后版本正确、原工作目录及系统凭据保留，安装取消后旧版本可再启动。另需验证无 Release、缺附件、损坏附件、网络失败及卸载保留数据。

随包媒体的公开再分发准备状态见 [Windows 随包媒体工具](windows-media.md)。本次实现没有发布 Release，也没有在用户机器上执行覆盖安装。
