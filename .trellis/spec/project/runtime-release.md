## 10. 运行与发布

### 10.1 源码开发

统一开发入口 `uv run python scripts/dev.py`；前端 pnpm，开发依赖安装走项目 setup 脚本。开发环境 FFmpeg / ffprobe 需 PATH 可用；冻结运行时仅使用随包工具，见 [§10.2](runtime-release.md#102-windows-桌面与安装器)。后端更改后重启统一启动器再刷新。

### 10.2 Windows 桌面与安装器

[项目规格索引](index.md) 顶部的规格版本同时作为应用版本：界面显示、原生程序版本和安装器版本均在构建时读取该值；缺少有效版本时构建失败。Rust 和前端包的内部包版本不作为应用版本。

原生开发版使用橙色标记的应用图标，正式版使用蓝色标记的应用图标，以便在窗口和任务栏区分。

DesktopSession 收到三个后台角色的就绪报告后，使用带会话令牌的 `GET /api/v1/health` 验证回环 API 可用。健康检查处理时只返回固定状态，启动就绪判定独立于项目列表查询耗时。

安装器构建入口为 [scripts/build-windows-installer.ps1](../../../scripts/build-windows-installer.ps1)，使用 [Inno Setup 脚本](../../../packaging/windows/installer.iss) 生成当前规格版本的 `.exe` 与 SHA-256 校验附件。构建步骤见 [Windows 安装包指南](../../../docs/windows-installer.md)，应用内手动更新与发布附件约定见 [软件更新](../../../docs/software-updates.md)。2026-11-15 整理时，本地已有 0.2.154 安装器和构建清单；产物存在不代表干净系统、完整业务或覆盖安装验收通过。

生产桌面由 DesktopSession 管理本地会话，承载同源静态工作台。早期 PyInstaller 单目录最小测试程序已通过真实回环 API 验证会话认证、项目列表与空闲退出；Tauri release 程序也已实际构建，并在无开发工具 PATH 的中文目录验证 WebView 项目列表、令牌内存交接及宿主进程组清理。生产入口首次显式选择统一工作目录，定位配置独立于工作数据；启动前校验原绝对路径、当前数据身份、关键数据库及可写性。原位置失效时停在修复页，不启动后台或新建替代库；恢复原路径后可重试，定位配置丢失可重新关联原位置的当前格式数据。工作目录更换须在本地设置确认并重启，仅重置定位配置；不移动、改名或删除原目录及其中的用户数据，不提供旧业务格式迁移。安装器及活动任务的完整生命周期验收仍按对应工单分别记录；构建、边界和实际证据见 [Windows 生产桌面会话](../../../docs/windows-session.md)。

Windows 桌面 API 和后台角色启动后，将系统标准句柄同步到当前 Python 输入输出流，再启动网络子进程，避免冻结运行时在嵌套子进程初始化时阻塞。安装器构建启用验证时，必须通过冻结会话、媒体及 OSS 子进程验证；OSS 验证使用隔离中文工作目录与本地 HTTPS 服务，覆盖真实子进程上传成功及 403 权限错误，不使用真实凭据或访问云端。

冻结桌面程序关闭初始化页或工作台窗口时会隐藏到系统托盘，保留 WebView、页面草稿和已启动会话；首次关闭显示后台运行及托盘操作说明。托盘菜单可恢复窗口或显式退出。Windows 单实例对象以 Tauri 应用标识、当前用户 SID 和当前交互会话命名，并使用当前用户默认 ACL；同一会话再次启动应唤回现有窗口，不创建第二套 Tauri 会话或后台服务。托盘 / 单实例验收已结合代码测试和用户桌面反馈完成；实际验证来源及此前一次未观察到唤回的记录见 [Windows 托盘与单实例](../../../docs/windows-tray.md)。工单 05 的活动任务退出确认、媒体检查点暂停及手动恢复已实现，退出命令错误恢复也已修复；用户已在 Windows 隔离程序中手动验证退出并暂停正常，工单标记完成。工单 06 已实现 ASR 与 OSS 网络等待进程中断、显式退出记录及启动后重排；本机断开不代表云端撤销，直接重发可能重复执行并产生费用；用户已用真实云端完成冻结桌面验收，工单标记完成。工单 07 将 ASR 后的文本选片同样放入可终止子进程：显式退出不等待模型响应，下次启动直接重排并只重发文本步骤，已成功的 ASR 分段与全量对话复用；已保存的选片决策不重复请求，模型拒绝、无效响应和普通网络故障（包括恰在退出时返回的）仍按失败与手动重试处理，被接管的旧执行者迟到响应不会覆盖新决策；冻结桌面验收待完成。相关验收状态和限制见工单记录及 [Windows 托盘与单实例](../../../docs/windows-tray.md)。

### 10.3 验收记录的适用范围

Windows 应用打包规格与分票记录见 [Windows 应用打包](../../../.scratch/windows-packaging/spec.md)。当前目标是用户个人本机安装和使用，不包含商店上架或公开分发。工单 01、03、04 已完成当前范围验收；工作目录准备仍有验收缺口。托盘首次关闭提示、恢复、同会话重复启动且进程数不变、退出后进程清理及剩余隐藏活动 / 用户隔离验证已获用户反馈正常，工单 04 标记为 `resolved`。本文不把这些能力等同于安装包的完整验收。

工单 03 的冻结媒体运行时固定使用随包 FFmpeg / ffprobe 8.1，启动前校验工具、许可证、上游说明和媒体来源清单的哈希，不读取全局 PATH 或开发媒体环境变量作为回退。Gyan 发布 ZIP 已按官方 SHA-256 校验，其 FFmpeg、ffprobe、许可证及 README 成员哈希与锁定运行时一致；固定 FFmpeg 主源码及许可证已取得。Gyan 静态构建其余外部库完整源码、精确许可证和构建配方仍未齐备，因此 `redistribution_ready` 保持为 `false`，仅表示尚未完成公开再分发准备；不影响工单 03 在个人本机使用范围内标记完成。原生文件选择器导入已获用户确认正常；隔离合成视频的导入任务、6 秒 / 160×120 探测结果、导入副本归属及原视频哈希已只读核对。当前无付费自动验收使用成功缓存 fixture；资源来源、构建步骤和验收状态见 [Windows 随包媒体工具](../../../docs/windows-media.md)。

Windows 桌面会话、随包媒体、托盘及安装器的实现与验收分别记录，不能将早期测试程序的“不是安装包”或某张工单完成推广为当前全部产品状态。源码阶段的验证记录见 [docs/IMPLEMENTATION_STATUS.md](../../../docs/IMPLEMENTATION_STATUS.md)；Windows 安装、更新及完整业务仍按 [打包验收清单](../../../.scratch/windows-packaging/acceptance-checklist.md) 和 [完整安装包交付工单](../../../.scratch/windows-packaging/issues/12-windows-release-acceptance.md) 的证据逐项确认。
