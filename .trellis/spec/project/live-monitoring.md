### 2.4 抖音直播监控

#### 页面

- 页面顶部为监控工具栏，下方并排显示直播间列表和所选直播间详情。异常筛选包含监控错误，以及最近场次仍在录制时的商品列表 / 商品连接错误。场次结束后，商品错误仅在该场次的商品讲解卡片中展示。“添加直播间”按钮打开弹窗，直播间链接与可选备注名称上下排列。弹窗支持 Esc、点击遮罩及取消按钮关闭，成功添加后自动关闭。桌面端工作区填满主内容区剩余高度，直播间列表及详情卡片各自在卡片内滚动。窄屏恢复页面自然滚动。页面采用主题语义色区分主要操作和状态，颜色与文字共同表达状态。
- 左侧直播间卡片支持按名称 / 链接搜索及全部 / 开播中 / 录制中 / 异常筛选，进入页面默认选择按本机保存顺序排列的第一个直播间；选择后在刷新时保留。列表项只显示名称、异常标记、开播状态、录制状态和场次数，不显示商品。开播状态取最近一次检测结果，标签在前：已开播 / 未开播；检测失败显示“检测异常”，尚未检测显示“等待检测”，悬停显示检测时间。只有正在录制时才额外显示“录制中”标签。卡片底部固定展示所选直播间：名称、链接、最近检测、录制策略、当前设置摘要、检测异常及录制 / 移除操作；最近检测显示“最近检测 MM/DD HH:mm:ss（x分钟前）”，分钟数向下取整且不小于 0，每 5 秒更新，尚未检测时显示“最近检测 尚未检测”；直播间链接在系统默认浏览器打开，录制中移除按钮禁用，须先停止录制。窗口可见时列表每 5 秒同步，窗口隐藏或最小化期间暂停同步、恢复可见时立即同步一次；录制与开播检测由后台进程执行，不受影响，开播检测仍为 20 秒。每次同步读取全部直播间的状态与当前日期窗口内的场次摘要，并只读取所选场次的完整详情；点击其他场次或切换直播间时读取对应详情，读取完成后更新内容卡片。
- 直播间列表可通过拖拽手柄或方向键排序。手柄贴紧卡片左边缘，旁边紧接卡片内容，悬停或键盘聚焦时用独立底色突出手柄。排序保存在当前客户端本地；首次展示按开播状态和名称排列，新增直播间追加。搜索、筛选及轮询不改变保存的顺序；筛选时只调整可见直播间的位置，隐藏项相对位置不变。
- 每个列表项右上角有设置图标，点击展开浮层，可分别开关“开播自动录制”、“开播提醒”、“下播提醒”和“切分完成提醒”（Windows 通知）。设置保存后立即生效，新添加的直播间默认全部开启。页面有其他操作进行中时开关禁用；保存失败时开关恢复为已保存的值。
- 录制操作按设置显示：开启自动录制且未手动停止时，只显示“发生开播后自动录制”的说明，不显示开始按钮；关闭自动录制、或本次直播已被手动停止时显示“开始录制”，录制中显示“停止录制”。开始录制仅在直播间已开播时可用，未开播时按钮禁用并提示。手动开始录制请求成功后回到该直播间的今天窗口，并选中当前录制场次，使商品讲解与商品片段同步展示本次录制；若录制工作进程尚未创建场次，则在后续刷新出现录制中场次时完成一次跳转。等待期间主动切换场次、日期、直播间或停止录制会取消此次跟随；跳转完成后继续保留用户后续的手动选择。
- 右侧顶部为横向录制时间线，替换原场次下拉框，默认展示当前直播间今天 00:00–24:00 的录制活动，选择日期后展示所选日期全天。每个时间段代表一次录制场次，保留停录间隙；刻度按本机时间显示 00:00、06:00、12:00、18:00、24:00。跨窗口场次只绘制交集并标记延续，标题栏显示“当前选择：”及已点击场次的完整起止时间、完整时长和状态；录制中显示“至今”，完整时长和区块终点计算至当前时刻，未来时段保持留空。同一天每 5 秒成功刷新后只更新内容，不移动窗口边界；默认今天模式跨午夜后展示新一天。点击时间段选择整个场次并更新标题栏“当前选择”；悬停或键盘聚焦只改变区块视觉状态，不改变当前选择摘要；选中场次保留高亮。默认选择窗口内录制中场次，否则选择开始时间最晚的场次，切换直播间重新选择；轮询和新场次不抢占手动选择。今天无场次时显示“今天无录制，可选择其他日期”，时间线显示空状态，两张内容卡片为空，不回退到窗口外历史场次。已选场次因跨日移出窗口时仍保留两个内容卡片，通过稳定标识持续更新详情，提示“所选场次已不在当前时间范围内”，可点击“查看该日期”进入该场次开始日期的自然日窗口。仅在详情读取成功且明确不存在时，回退至窗口内开始时间最晚的场次；无候选则清空。请求失败保留上次成功的窗口和内容，显示失败状态；切换直播间、选择或卸载后忽略旧请求结果。时间线持续保留选中场次，包括其移出窗口之后；当前已结束场次标题栏摘要旁提供“删除场次”按钮；录制中的场次禁用。确认删除会删除该场次的讲解记录、商品事件、场次索引及未导入的源媒体文件 / 商品片段文件，显示待清理数量和估算体积；已导入片段、被视频项目引用的文件及项目素材保留。场次存在录制、导入或商品片段活动任务时拒绝删除。
- 商品讲解与商品视频片段为两张并排卡片，填满内容区可用宽度，宽度比例为 2:3；空间不足时垂直堆叠。
- 时间线使用 daisyUI Calendar（Cally）与 Dropdown 展示中文日期选择器，按钮默认显示今天日期，日历默认选中今天；点击日期按钮展开日历，选中后收起；点击外部或按 Esc 关闭，支持清空日期。允许选择今天及更早日期，未来日期禁用。所有日期窗口按本机时区从当天 00:00 至次日 00:00 计算，夏令时日期遵循实际自然日长度；历史日期固定不随轮询或跨日改变。清空日期、选择今天或点击“回到今天”恢复默认今天模式，并在跨午夜后跟随新一天。切换日期保留仍相交的已选场次，否则选择窗口内开始时间最晚的场次；无场次显示“当天无录制”，下方两张内容卡片为空。切换直播间保留日期，并按新直播间窗口内录制中优先、否则最新的规则选择。日期选择器左侧固定显示“前一天”按钮，点击后从当前选中日期（默认今天）按本地自然日切换至上一天，支持连续回溯及跨月 / 跨年，不按固定 24 小时减算；加载日期期间禁用。“回到今天”按钮固定显示，当前已是今天时禁用。每五秒后台同步不禁用日期控件、不插入可见读取提示，保持按钮布局和样式稳定；期间切换日期会使旧同步结果失效。仅首次加载或日期切换查询期间暂时禁用日期操作，读取状态通过无障碍提示表达，成功后同时更新窗口标识与内容；失败时保留原窗口并恢复日期，报告错误。直播间正在录制的状态和开始 / 停止控制根据直播间实时状态判断，不依赖日期窗口的场次列表。
- 日期控件包含“前一天”和“后一天”导航，按本地自然日移动并支持跨月、跨年；后一天在今天或加载日期时禁用，未来日期仍不可选。
- 场次记录结束时间来源 `end_time_source`：录制中为 null，正常停止或运行中检测到失败为 `observed`，应用启动恢复检查封存的异常场次为 `recovery_check`。列表和稳定标识详情查询均返回该字段。仅对 status=failed 且来源为 recovery_check 的场次显示“异常结束，结束时间可能晚于实际停录时间”；其他失败仅显示“异常结束”。录制活动时间不代表精确媒体覆盖范围，不追溯旧数据的实际停录时刻，不新增历史数据库迁移或兼容分支。
- 商品讲解轨位于录制场次卡片内、录制时间线下方，横向占满卡片内容宽度，不使用独立卡片或彩色区块背景，轨道高度紧凑；无所选场次时在同一位置显示空轨提示。讲解区间只绘制细线和起止边界，不显示商品名称；颜色由商品 ID 稳定生成，使用高饱和色相，不依赖有限循环色板；同一商品的轨道、讲解列表时间、选中态及商品片段“所属讲解”时间标签使用相同颜色。不同 ID 的颜色理论上可能相同或视觉接近。点击未选中的区间选中该次讲解并联动高亮讲解列表，不立即显示拖动手柄；再次点击已选中的区间取消选中，同时清除列表高亮、隐藏轨道操作区并退出尚未提交的范围选择。点击其他区间直接切换选中讲解。选中后轨道操作区显示商品标识和“切分商品”；点击后才进入范围选择模式，讲解内可切分范围超过 20 分钟时默认选中起点开始的 20 分钟，否则选中全部；双端手柄可调整范围，拖动选区中段可整体平移，拖动任一手柄时，选中片段的时长接近 5 分钟倍数即吸附，不依赖片段在讲解中的起止位置，并提供明显吸附感；范围最短 1 秒，并提供“确认切分 / 取消”。录制中的场次默认范围截止到该次讲解内已封存内容，避免选择仍在写入的尾段；已结束场次可选至完整讲解结束时间，后台仍只处理已封存来源，未封存、缺失或异常来源依既有规则等待、部分确认或报错。确认只提交当前选中的起止范围；仍按当前缺失来源规则要求用户确认仅切可用来源。列表移除媒体块编号标签和范围调整按钮，保留商品信息、区间、时长、状态及错误。内部媒体分块仍用于异常恢复、局部转码、导入和长录制稳定性，用户不在场次详情中单独管理。
- “商品讲解”卡片标题旁显示商品监听状态和讲解次数；移除独立的“正在讲解 / 场次结束时讲解”卡片，“讲解变更”改为“讲解列表”。列表以持久化讲解区间为准，首次讲解也显示，同一商品多次讲解分别列出；当前讲解置顶，其余按开始时间倒序。选中行使用浅色背景和强调边框联动轨道。每条显示商品名称（缺失时显示商品 ID）、商品 ID、本场起止位置、已结束讲解时长、生成数量 / 待切数量 / 待封存部分 / 不足 1 秒说明，不显示媒体块编号或独立范围控件。商品监听说明通过标题右侧状态徽标的提示浮层展示，悬停或键盘聚焦可查看。连接中断、商品目录获取失败或连接后长时间未收到商品消息时，状态徽标以呼吸光晕提示。启用减少动态效果时显示静态光晕。商品目录错误和重试按钮位于列表上方。首次商品从录制开始计是剪辑区间规则，不代表已验证主播实际开始讲解的时刻。
- 内部 MPEG-TS 媒体分块不作为独立场次卡片呈现，也不提供用户侧筛选、导入、打开或删除分块的操作；分块用于连续录制恢复、商品讲解范围映射及切分任务。用户从商品视频片段卡片导入生成的片段项目。
- “切分商品”操作位于商品讲解轨道，与当前选中的讲解联动。点击后进入范围选择模式：当前可切分范围超过 20 分钟时默认选中前 20 分钟，否则选中全部。用户可拖动两端手柄调整起止位置，也可拖动两手柄间的选区整体平移；拖动任一手柄时，吸附点按选中片段的时长每 5 分钟递增计算，与讲解内的绝对起止位置及手柄本次拖动起点无关；最短范围 1 秒。确认仅提交所选范围与已封存媒体块的交集，同一次连续选区跨块时拼接为一个商品片段；不将其他可切分区间一并提交。当前讲解允许先切已封存部分，之后再次选择后补切新封存部分。任务进行中轨道操作显示“切分中…”并禁用，失败原因显示在对应讲解下。部分来源不可用时，先列出来源及原因，用户确认“只切可用部分”后才提交所选范围内剩余已封存来源；确认时来源再次变化须重新确认。没有已封存范围时禁用切分并说明等待封存，全部可用片段已生成时提示无需重复切分，不创建空任务。
- 讲解列表选中一个商品后，如果同一录制场次存在相同商品 ID 的多次讲解，在这些讲解行显示多选框，与“查询商品”同一行且垂直居中；同名但商品 ID 不同不视为同一商品。勾选两次及以上讲解时，商品讲解轨的“切分商品”按钮切换为“合并切分”，显示已选段数及按已封存可用来源累加的预计时长。合并按录制时间顺序拼接各次完整讲解的已封存可用部分，不提供可调整时间轨道，生成一个独立商品视频片段，不覆盖已单独切分的成品。任一所选讲解没有已封存可用内容时等待并提示，不创建部分合并任务；已封存来源缺失时，用户在商品讲解轨确认“只合并可用来源”后才提交。任务窗口快照保留每个来源的讲解 ID 并按时间排序；活动任务沿用来源媒体串行约束。
- “商品视频片段”列表显示商品名称（缺失时显示商品 ID）、状态（生成中 / 待导入 / 导入中 / 已导入 / 生成失败）、所属讲解起止位置（可点击，按讲解区间 ID 同步选中讲解列表与轨道，并将对应讲解滚动到可见位置；合并成品显示“所属讲解 N 次”并展开列出各来源）、片段在场次内的起止位置、实际时长、文件大小、失败原因及可展开文件路径；不显示内部媒体块序号。待导入显示“导入剪辑”，已导入显示“打开项目”，导入成功后将片段商品名称写入项目资料草稿。每个未失败的片段另有“打开”和“在文件夹中显示”；各片段可确认删除，生成中 / 导入中不可删除，已导入时只删监控记录并保留项目及其素材文件，未导入时同时删除片段文件；删除只允许操作直播录制目录内的片段。打开 / 删除路径不符或文件缺失时安全拒绝。页面内不嵌入片段播放器，避免 MPEG-TS 在浏览器 / WebView 中的兼容差异。空状态提示在讲解列表中点击“切分商品”。
- 监控备注名称可选；留空时首次解析直播间后使用抖音解析结果中的主播名称，解析前及解析不到名称时显示“抖音直播间”。用户填写的备注名称始终优先，不被自动名称覆盖。

#### 商品讲解轨预览

商品讲解轨支持鼠标悬停画面预览：鼠标首次进入时立即请求所在时间的静态缩略图并显示场次内时间；离开后再次进入时，命中缓存立即显示，未命中且没有在途请求则立即取图。轨道内移动时以一秒粒度更新，空闲时采用 100 毫秒限频合并而非反复重置计时，持续移动也会取最新位置，旧请求完成后立即跟进最新目标且跳过中间位置，拖动切分选区和手柄时同样可用；不会改变讲解选择或切分范围。预览按图片实际宽高比自适应横屏、竖屏和方形画面，等比完整显示、不裁切；图片最大显示宽度 238px、高度 270px，并按窗口剩余空间缩小。弹层挂载到页面顶层，优先在轨道上方显示，空间不足时改在下方，左右保持在窗口内；窗口缩放或页面滚动时隐藏，鼠标再次移动后重新定位。只读取本地已封存且可用的来源，未封存尾段、缺失文件及映射缺口显示明确提示。通过带本地会话认证的接口按需生成宽高均不超过 320px 的等比 JPEG，不调用云端模型、不预先扫描整场录制、不生成完整视频代理。前端至多一个在途请求并缓存 32 张，后端至多一个单线程 FFmpeg 解码并缓存 96 张，缓存仅驻留内存；抽帧优先从目标前 3 秒快速定位并核对实际帧时间，定位越过目标或无可用帧时扩大到前 15 秒，仍不准则从头定位；所有尝试共用 8 秒超时，繁忙请求直接返回，避免鼠标移动积压任务。离开轨道隐藏预览，切换场次 / 卸载释放前端缓存并忽略旧请求结果。右键商品讲解轨可选择“查看所在录制片段”：按右键时的位置锁定所属已封存来源，用系统默认播放器打开对应录制文件，并提示该位置对应的文件内时间；系统默认播放器从文件开头播放，由用户手动跳转，不生成额外预览视频。未封存、缺失或不可用来源禁用查看并说明原因，时间缺口不显示菜单；不改变讲解选择与切分范围，右键切分手柄不会启动拖动。菜单显示时暂停悬停取图，点击外部、按 Escape、滚动、缩放或切换场次时关闭。

商品讲解轨下方按场次累计时间每 20 分钟显示一个刻度，从 00:00 开始，按实际时长比例定位，与悬停和右键菜单时间一致；跨小时显示时分秒。末尾保留场次总时长，非整 20 分钟的末尾时间另起一行靠右显示，避免与最近刻度重叠；整 20 分钟时只显示一次。切分编辑期间刻度与轨道共用冻结的时间范围。

#### 监控与录制

- 监控目标只接受抖音直播间链接或抖音分享短链，不支持主播个人主页。后台监控进程与普通有限任务进程分离；录制及监控不依赖前端页面持续打开，但应用 / 监控进程退出时不保证继续运行。
- 监控状态与录制状态分开：新增或启动后即对全部直播间每 20 秒检测一次开播，没有暂停检测；不再提供“暂停监控”操作，开播检测常开。
- 默认每 20 秒解析一次直播状态。开播时启动 FFmpeg，将音视频流直接封装为本地 MPEG-TS，内部按约 1200 秒切换文件，不重编码；切换仅是媒体可靠性与恢复机制，场次详情和讲解流程按整场连续录制呈现。每次检测记录直播间是否开播及检测时间（`live_monitor_liveness`），与录制状态分开保存。录制目录为 `data/recordings/live/{monitor_id}/{session_id}/`；同一监控项的轮询只管理一个活动录制进程。
- 是否开始录制由设置决定：`auto_record` 开启时检测到开播即开始；关闭时需用户点击“开始录制”，该请求只对本次直播有效，直播结束后清除。用户点击“停止录制”会立即停止并封存，并把本次直播标记为已停止，之后即使 `auto_record` 开启也不再自动恢复，直到直播间离线；离线后该标记自动清除，下次开播按设置重新决定。
- 开播提醒：检测到直播间从离线变为开播时发送一次 Windows 通知中心提醒（标题为直播间名称，正文说明是否会自动录制），同一次直播只提醒一次，离线后重置。提醒开关按直播间保存在设置中；通知由后台监控进程通过 PowerShell 发送系统 Toast，不注册开机自启或常驻服务。
- 下播提醒：监控检测到直播间从开播转为离线时发送一次 Windows 通知中心提醒，完成录制收尾后通知；重复离线检测不重复提醒，设置按直播间保存。
- 商品切分完成提醒：商品切分后台任务全部成功后发送一次 Windows 通知中心提醒，失败、取消或暂停不提醒；设置按该商品所属直播间保存。提醒正文说明商品视频片段已生成。
- 直播离线、用户停止录制或录制进程退出时停止 FFmpeg 并完成当前场次收尾；只有 ffprobe 可探测的已封存媒体块可作为商品切分来源。商品视频片段通过现有 import 后台任务成为普通视频项目；用户在素材与粗剪页输入商品信息并主动启动分析。录制进程退出时按退出码区分正常结束与异常中断；异常退出保存退出码及 FFmpeg 日志末尾，监控项标记异常并保留中断标记，直播间离线后自动恢复，当前仍开播时也可手动开始录制。
- 封存媒体块使用 ffprobe 的标准输出解析 JSON 时长，诊断输出与 JSON 分开读取；媒体任务日志仍保留两路输出。探测失败记录日志并在 60 秒冷却后重试，最终封存扫描可立即再试；正在写入的尾块不提前探测。没有活动录制时，监控后台为当前格式的已结束场次补齐未知时长，每轮最多探测一个现存媒体块、超时 5 秒；单个失败文件的冷却不阻塞其他待补齐文件。读取场次 / 切分计划的 GET 请求不执行媒体探测。补齐只更新媒体块元数据，保留导入状态、项目 / 任务关联及场次结束时间来源，不修改源视频、不按固定分段长度估算；文件仍不可探测时继续报告时长未知。
- 状态包括等待检测、未开播 / 已开播、录制中、检测异常 / 录制失败；每个场次记录起止时间，内部媒体块记录文件路径、大小、时长及封存状态，不作为可单独导入的项目素材呈现。直播流 URL 不持久化，解析错误不保存临时媒体凭据。

#### 商品平台与目录更新

- 添加直播间时可选择星斗、达多多、星动力或不绑定。已有直播间在列表的齿轮菜单中点击「绑定平台」或「修改绑定」，通过弹窗保存。平台绑定字段的标签和控件同行对齐。每个直播间最多一条平台绑定，同一平台可绑定多个直播间。达多多绑定填写该直播间的 `ipId`。星动力从当前账号的签约达人列表选择，并保存该达人的 `ipId`。
- 应用启动时后台更新已绑定达多多的直播间。「商品讲解」卡片在「讲解列表」标题旁显示平台、更新按钮、进度、上次成功时间和商品数，无所选场次时也可更新。同一直播间的更新请求合并。同步请求每页 50 条，省略日期参数，以第一页的总数为准。后续页返回 `total=0` 时继续累计该页商品。提前遇到空页、累计超出首页总数或后续页报告不同的非零总数时，本轮更新失败。全部页面校验通过后一次替换本地目录，更新失败时继续查询同一绑定此前的完整目录。修改平台或查询标识会移除旧绑定的目录。
- 商品讲解列表传直播间 ID 与关键词，由后端选择星斗在线搜索或达多多本地搜索。达多多优先匹配完整商品名，再匹配名称包含关键词的首条。查询弹窗省略平台名，达多多结果展示商品信息。未绑定或尚未完成首次同步时显示对应提示。添加橱窗适用于星斗。
- 星动力直播间在「商品讲解」打开「星动力商品列表」，也可从某条讲解按名称搜索。后端从直播间绑定取得经当前账号校验的 `ipId`，调用 `POST /frontend/product/list-by-ip`，每页 20 条，关键词为空时查看全部。查询弹窗支持分页并从当页选择商品查看详情。
- 导入商品视频片段时，项目记录录制场次所属直播间 ID，参考图查找使用该直播间当前的绑定。

#### 商品监听

- 当前录制场次使用单条 Python WebSocket 商品连接，不建立并行影子连接。直播间首次录制或尚未成功取得商品目录时，异步 POST `/live/promotions/page/` 空请求体，按 `offset` / `limit` 遍历全部分页，解析 `promotions[].promotion_id` / `title`；首次查询可用本次实时响应的 `top_promotion` 初始化“当前讲解商品”。已有目录时启动新场次或重连不请求列表，等待本场商品消息确认当前商品，不复用上一场当前商品或旧的 `top_promotion`；但每个新场次在消息连接建立前额外请求一次单页目录（`limit=1`），仅用本次响应的 `top_promotion` 初始化当前商品，不改动缓存目录、不重试、失败只记调试日志，避免整场没有商品消息时讲解列表完全为空。请求沿用会话 Cookie，并发送可从 Cookie 取得的 `webid`、`uifid`、`x-secsdk-csrf-token`；进程内所有商品列表请求全局间隔至少 1 秒，空响应 / 传输异常 / HTTP 408、429、5xx 最多请求 3 次。商品目录按直播监控项 `monitor_id` 隔离保存于 SQLite，同一直播间跨场次和应用重启复用，当前商品、讲解区间及目录错误仍按场次隔离。成功获取的空目录有独立成功标记，不视为未获取。仅在完整分页成功后，以单个事务替换该直播间目录并保存成功时间，网络 / 响应 / 分页失败时保留上次目录。请求失败时保存脱敏后的请求诊断、HTTP 响应正文或传输异常，并在商品区域显示红色可展开详情；分页异常还展示失败页游标和已收集条数。不保存 Cookie、CSRF 值或签名 URL。每次观察到商品消息中的商品 ID（含重复 ID）先查该直播间目录；命中名称不请求，未命中才异步刷新完整目录并补全本场缺失名称。每个直播间同时仅一个刷新，刷新期间收到的未知 ID 合并到该次结果处理；自动全量刷新开始时间至少间隔 60 秒，冷却期间的待处理 ID 合并并在允许时请求。成功刷新仍缺失的 ID 冷却 5 分钟，失败时冷却 60 秒，冷却与最后请求时间按直播间持久化；须在冷却结束后再次观察到该 ID 才触发下一次刷新，不永久放弃。无初始获取需求、未知商品消息或手动重试时不刷新；页面 5 秒轮询只读取本地状态。仍未找到或刷新失败则显示商品 ID。已知 ID 的名称可能保持旧值，直到下次刷新。初始查询按请求开始时间落库，较晚返回的查询结果不得覆盖之后已收到的更新。首次观察到的 WebSocket 商品只建立基线，不伪装成切换事件；之后商品 ID 变化须由同帧或 5 秒内 `LivePopMessage` 中相同商品 ID 佐证，确认后写入正式商品事件表并同步更新当前商品，来源标记为 `python_live_shopping`。`WebcastProductChangeMessage` 暂不单独写正式事件。商品 ID、源时间戳、本地接收时间分别持久化。商品标题解析失败不影响商品状态，页面继续显示商品 ID；不在 WebSocket 收帧 / ACK 回调中等待 HTTP。讲解类型目前仍留空。页面展示当前 / 场次结束时商品、商品连接状态和正式变更事件时间线；不采集、保存或展示录制期间的商品消息诊断样本。商品事件监听只在录制场次内运行，停止 / 结束录制时关闭。商品区域将连接状态显示为“商品消息连接已建立”；商品列表获取错误或商品消息连接错误时，录制中的场次显示“重试商品连接”，商品列表错误时手动重试立即刷新目录，可跳过自动冷却；消息连接正常时复用连接。仅消息连接错误时只重连消息，保留已有目录；两者均错误时重连并刷新。已有刷新任务时复用该任务，不增加并行或后续重复请求；操作不停止 FFmpeg 或清空已有讲解记录。重试中禁用重复请求，已结束场次不提供该操作。
- 商品变更按场次持久化商品 ID、可用的商品名称、`explain_type`、直播消息时间与本地接收时间；事件列表用于核对讲解切换点。消息时间与接收时间相差超过 5 分钟时使用接收时间作为锚点。`explain_type` 保留原始值，不在真实直播样本确认前将其解释成开始 / 结束状态。
- 独立实验模块仍保留实时探针，用于单独报告 HTTP 会话、WebSocket 消息类型和 ACK；短链只允许 HTTPS 抖音域名逐跳重定向，日志不输出 Cookie 与签名查询串。`a_bogus` 与安装的 `streamget` 固定时钟向量一致；PushFrame payload 同时依据 `payload_encoding` 和 gzip 文件头 `1f 8b` 解压。Python 商品事件已在真实商品切换样本中验证，后续仍需核对长时间连接稳定性和商品事件时间与录制媒体时钟的误差。

#### 商品讲解区间与商品片段

- 当前商品 ID 每次变化（含初始化当前商品）都记录一个商品讲解区间：首个商品从本场录制开始计，后续商品从本机收到切换消息的时间计，并结束上一区间；场次停止时未结束的区间以停止时间收尾。仅更新商品名称不产生新区间，空名称区间会被随后查到的名称回填。
- 商品片段只由用户手动触发，录制结束不自动生成。`POST /live/product-periods/{id}/product-clips` 按单次讲解创建 `live_product_clips` 普通后台任务（任务页可暂停 / 取消 / 重试）；任务 payload 使用 `period_id`、`session_id`、本次已封存来源的 `windows` 快照，不再使用分段范围任务协议。同一讲解有活动任务时复用该任务；不同讲解的任务涉及相同分段时提示等待，按录制来源串行执行切分。
- 来源关联、界面时间和任务窗口统一由讲解区间与连续媒体分块的实际时长累计计算；保留已删除分块的时长参与累计，不按固定 20 分钟估算，不回退到文件扫描时间。分块编号按录制文件末尾的零起始序号加一确定，删除前块不会使后块重新编号。编号缺口或已封存分块时长未知时报告映射错误，拒绝按估算位置切分。
- 当前讲解与录制中媒体分块仍显示关联，但只有已封存来源进入任务。冻结的窗口裁剪到源分块内，转换为该文件内本地秒数，至少 1 秒才生成。TS 分块在任务临时目录中仅复制音视频流，无损重封装为带索引的 MKV，避免直接 seek TS 丢失选区画面；不转码整块录制，不生成长期保留的剪辑源 MP4。按各来源的本地起止时间准确 seek，并在同一个 FFmpeg 编码流程中完成选区裁剪与跨文件拼接；同一次连续选区只生成一个 MP4 商品片段，不因源文件边界拆成多个结果，也不再分别编码后重编码。拼接时统一画面尺寸、帧率与音频格式，无音轨来源补静音；单次讲解范围选择不提供多个独立区间。
- 商品片段优先使用可用的 H.264 硬件编码：依次检测 NVIDIA NVENC、Intel QSV、AMD AMF，须通过实际短视频编码探测，不能仅依据 FFmpeg 列出的编码器判断可用；按配置的 FFmpeg 路径在进程内缓存探测结果，重启后重新检测。无可用硬件或实际硬件编码失败时，自动使用 libx264 重试同一选区一次；CPU 编码与滤镜线程预算为逻辑处理器数的一半、至少 1 且最多 4，多个来源分配输入解码线程。解码、滤镜与音频编码仍可能占用 CPU，不承诺固定占用比例。暂停 / 取消直接中断，不触发 CPU 重试；失败尝试的输出先清理，最终结果仍通过探测后原子发布，编码日志记录在应用 logs 目录。
- 部分来源缺失时返回 `state=confirmation_required`、`missing_segments` 和 `available_count`，不创建任务；请求体 `confirmed_missing_segment_ids` 必须与当前全部缺失来源 ID 集合一致才允许部分切分，新增缺失需要再次确认。没有任何可用来源且没有待封存来源时返回 409；等待封存、全部已生成或没有至少 1 秒的可切区间返回 `state=noop` 和中文原因，不创建任务。`GET /live/product-periods/{id}/split-plan` 与场次详情的 `product_periods` 使用相同的来源关联与任务状态。
- 片段写入该场次录制目录，文件名为 `商品片段_{首个来源分块序号}_{商品名}_{区间 ID 后 8 位}.mp4`；商品名去除 Windows 非法字符并截取 48 字符，为空时使用商品 ID。同一输出仅保存一条片段记录，以首个来源分块与讲解区间作为唯一锚点，起止时间覆盖本次全部处理窗口；讲解来源状态按输出覆盖的时间范围关联，跨文件输出不会导致后续来源被重复补切。任务 payload 额外保存本次 `selection.start/end` 范围快照；状态为生成中（processing）→ 待导入（completed）或生成失败（failed，保存异常摘要）；补切跳过已生成 / 导入中 / 已导入部分，只生成新封存、失败或中断的部分。内部裁剪文件仅保存于任务临时目录，全部裁剪及拼接成功后才发布最终片段；任一环节失败则整次任务失败并清理临时文件，重试整次选区，不发布不完整片段。原始录制分块不被修改。
- 待导入片段通过 `POST /live/product-clips/{id}/import` 排入普通 import 任务，状态改为导入中，成功后为已导入并关联视频项目；导入任务失败或取消后恢复为待导入。
- 时间轴映射为“本机事件接收时间 − 本场录制开始时间”，对应连续封存 TS 的累计时长。商品源时间与媒体时钟误差、直播消息接收延迟和关键帧切点精度仍需真实录制验证。

- 商品消息连接失败或断开后，录制期间自动重连：首次立即尝试，连续失败后按 5、10、20、40、60 秒退避并加入 0%–20% 随机提前，最长间隔 60 秒；连接稳定 60 秒后重置退避。等待期间展示预计等待时间，允许手动立即重试，同一场次不并行建立连接；停止录制或结束场次取消重试。仅长时间没有商品消息不触发重连，断线期间遗漏的消息不保证补回。自动重连不停止录制或清除已有商品记录。

#### 删除与数据

- 内部媒体块不提供用户侧独立删除操作，按场次删除规则清理未导入且未被项目引用的源文件；编号、时长和时间范围仍用于讲解来源映射。商品视频片段可单独删除；生成中 / 导入中禁止删除，未导入片段连同直播录制目录中的片段文件删除，已导入片段只删除监控记录并保留视频项目及其素材文件。
- 删除场次会删除该场次的监控元数据、分段索引、商品事件、商品讲解区间、商品片段记录、当前商品、目录错误和监听状态索引；保留该直播间可跨场次复用的商品目录、成功标记及请求冷却记录；同时删除未导入且未被项目引用的场次目录文件。已导入片段、被视频项目引用的文件及其项目素材保留；录制中、导入中或商品片段任务活动时不能删除。移除监控项会删除监控元数据、控制设置及场次、分段、商品事件、商品讲解区间、商品片段、当前商品、商品目录和监听状态索引，但永不删除本地录制文件、商品片段文件或已导入项目；正在录制时不能直接移除，先停止录制并封存。停止录制会终止当前 FFmpeg 进程、保存尾段，并标记本次直播不再自动录制；开播检测不受影响。
- 监控、录制、商品事件 / 区间 / 片段及监听状态保存在独立 SQLite 表，不伪装成普通可租约的后台任务；商品片段导入使用普通 import 任务，商品片段切分使用普通 `live_product_clips` 任务。商品片段导入仅自动带入片段名称，其他商品资料仍由用户填写。内部媒体块不单独导入为视频项目。首版不提供自动 ASR、定时录制、主播主页 / 多平台、断流自动恢复或远程回看。
