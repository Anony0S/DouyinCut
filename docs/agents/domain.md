# Domain Docs

This repo uses a single domain context.

Before exploring a topic, read:

- `GLOSSARY.md` at the repository root, if present
- Relevant ADRs under `docs/adr/`, if present

Use glossary terms consistently in issue titles, specs, refactor proposals, hypotheses, and tests. If a needed term is missing, record it for domain modeling. Surface conflicts with existing ADRs instead of silently overriding them.

Expected layout:

- `GLOSSARY.md`
- `docs/adr/`
